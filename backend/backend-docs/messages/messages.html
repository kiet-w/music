Messages Module

Quản lý hệ thống tin nhắn (chat) và lời mời kết bạn (friend requests). Cung cấp gửi tin nhắn trực tiếp, lịch sử trò chuyện, tạo lời mời kết bạn có hạn 24 giờ và xử lý token bảo mật.

1. Tổng quan Kiến trúc (Component Overview)

Module Messages chịu trách nhiệm quản lý hai luồng nghiệp vụ chính: hệ thống tin nhắn giữa người dùng và quản lý lời mời kết bạn. Kiến trúc được chia thành các layer rõ ràng nhằm đảm bảo Separation of Concerns và hỗ trợ khả năng Test & Bảo trì (Testability) một cách tốt nhất.

Tại sao tách các layer?

  • Tách biệt mối quan tâm (Separation of Concerns): Controller chỉ lo liệu phần HTTP (param, body payload, guard). Service đảm nhận quy tắc nghiệp vụ phức tạp (ví dụ: tạo hạn 24 giờ, sinh mã token, kiểm tra không được tự kết bạn). Repository lo liệu cách giao tiếp với Prisma ORM, chẳng hạn viết query OR để lấy hội thoại hai chiều.
  • Khả năng Test & Bảo trì: Việc tách logic CSDL xuống Repository giúp viết Unit Test cho Service dễ dàng thông qua mocking mà không phụ thuộc cứng vào Prisma.

4. Phân tích chi tiết Controller, Service, Guard

4.1. MessagesController (messages.controller.ts)

Các Decorators:

  • @ApiTags('messages'), @Controller('messages'): Gắn Swagger tag và prefix route HTTP.
  • @ApiBearerAuth(): Yêu cầu đính kèm token Bearer.
  • @UseGuards(JwtAuthGuard): Bắt buộc JWT Token hợp lệ để truy cập.
  • @UseInterceptors(ClassSerializerInterceptor): Tuần tự hóa và loại bỏ trường nhạy cảm dựa trên khai báo của DTO.

Các endpoint (Public Methods):

  • create(user, createMessageDto): Nhận data từ body (content, receiverId) và ID người gửi từ token -> gọi MessagesService.create(). Trả về MessageResponseDto.
  • findAllByConversation(user, otherUserId): Lấy ID người kia từ Param và bản thân từ token -> gọi MessagesService.findAllByConversation(). Trả về [MessageResponseDto].

4.2. MessagesService (messages.service.ts)

  • create(senderId, createMessageDto):
    Sử dụng messageRepository.create() lưu tin nhắn mới. Sử dụng cú pháp connect của Prisma để nối ID sender và receiver.
  • findAllByConversation(userId1, userId2):
    Gọi messageRepository.findConversation() để truy xuất toàn bộ cuộc hội thoại.

4.3. MessageRepository (message.repository.ts)

  • Kế thừa BaseRepository của Prisma.
  • findConversation(userId1, userId2): Tìm kiếm bằng điều kiện OR: (senderId = userId1 VÀ receiverId = userId2) HOẶC ngược lại. Sắp xếp tin nhắn orderBy: { createdAt: 'asc' }.

4.4. FriendRequestsController (friend-requests.controller.ts)

Các Decorators tương tự: @ApiTags, @UseGuards(JwtAuthGuard), @ApiBearerAuth().

  • createInvite(req, dto): Tạo lời mời với receiverId (optional).
  • getInviteInfo(token): Public API. Lấy thông tin lời mời từ token.
  • acceptInvite(req, token): Chấp nhận lời mời dựa trên token và ID người dùng đăng nhập.

4.5. FriendRequestService (friend-request.service.ts)

  • createInvite(senderId, dto): Tính expiresAt (+24 giờ). Sinh token dạng UUID v4. Gọi repo tạo lời mời.
  • getInviteInfo(token): Lấy lời mời. Nếu không có: ném NotFoundException. Nếu status khác PENDING: ném BadRequestException. Nếu quá hạn expiresAt: cập nhật thành EXPIRED và ném BadRequestException.
  • acceptInvite(token, receiverId): Verify bằng getInviteInfo(token). Check không tự mời bản thân. Cập nhật status = ACCEPTED.
  • checkConnection(userId1, userId2): Kiểm tra trạng thái bạn bè (có một `FriendRequest` trạng thái `ACCEPTED`).

5. DTOs (Data Transfer Objects)

  • CreateMessageDto: Yêu cầu content và receiverId.
  • MessageResponseDto: id, content, senderId, receiverId, createdAt.
  • CreateFriendRequestDto: Cho phép receiverId là optional UUID.
  • FriendRequestResponseDto: id, token, senderId, receiverId, status, expiresAt, createdAt.

6. Các Pattern quan trọng

Pattern 1: Lazy Update (Cập nhật trễ trạng thái hết hạn)

if (new Date() > invite.expiresAt) {
  await this.friendRequestRepository.update({
    where: { id: invite.id },
    data: { status: RequestStatus.EXPIRED },
  });
  throw new BadRequestException('Invite link has expired');
}

Tại sao dùng pattern này? Tránh overhead cho hệ thống khi không cần các tác vụ chạy nền (Cron jobs) quét DB đổi trạng thái định kỳ. Việc update chỉ xảy ra khi User truy cập tài nguyên (VD: API getInviteInfo).

Pattern 2: Biến Query Params thành Prisma OR condition

return this.findMany({
  where: {
    OR: [
      { senderId: userId1, receiverId: userId2 },
      { senderId: userId2, receiverId: userId1 },
    ],
  },
  orderBy: { createdAt: 'asc' },
});

Tại sao dùng pattern này? Rất tự nhiên để quét một hội thoại 2 chiều trong cơ sở dữ liệu.

7. API Design Review

  • POST /messages — 201 Created ✅
  • GET /messages/:userId — 200 OK ✅
  • POST /friend-requests/invite — 201 Created ⚠️ (Thiên hướng verb-oriented, nên dùng /friend-requests)
  • GET /friend-requests/info/:token — 200 OK ⚠️ (Thiên hướng verb-oriented, nên dùng /friend-requests/:token)
  • POST /friend-requests/accept/:token — 201 Created ⚠️ (Tốt hơn là PATCH /friend-requests/:token/accept)

8. Cách Debug khi gặp lỗi

Lỗi 400 BadRequest khi "Get Invitation Info" hoặc "Accept Invite"

  • Xem thông báo lỗi trả về.
  • Nếu "Invite link is already X", kiểm tra lại trong database cột status đã thành ACCEPTED hay EXPIRED chưa. Lời mời chỉ được thao tác khi còn PENDING.
  • Nếu "Invite link has expired", kiểm tra cột expiresAt. Hệ thống tự update thành EXPIRED nếu gọi API quá thời hạn này.
  • Nếu "You cannot accept your own invite", đảm bảo người đăng nhập không phải chính là senderId.
rtk grep "Invite link has expired" src/messages
# Test DB query
SELECT id, token, status, "expiresAt" FROM "FriendRequest" WHERE token='<token>';

Lỗi 401 Unauthorized

  • Kiểm tra request đã đính kèm Bearer token hợp lệ trên Header chưa.
  • Endpoint getInviteInfo là ngoại lệ vì nó Public (không guard).

9. Đánh giá — Đã tốt chưa?

✅ Đã làm tốt

  • Tách Repository Layer: Giữ nguyên sự thuần túy của Service Layer chỉ cho Business Logic.
  • Lazy Update Status: Tiết kiệm tài nguyên không cần cron job.
  • Tính năng Invitation Mở: Cung cấp tùy chọn tạo link với receiverId là optional, có thể chia sẻ rộng rãi.

❌ Cần cải thiện

  • Bảo mật gửi tin nhắn: Hiện tại bất cứ ai cũng nhắn được cho người khác (tiềm ẩn spam). Cần tích hợp checkConnection để đảm bảo đã kết bạn mới được nhắn. Ném lỗi 403 Forbidden nếu không phải bạn bè.
  • Thiếu phân trang (Pagination): findConversation đang lấy toàn bộ log tin nhắn. Cần implement cursor-based pagination hoặc skip/take để giảm tải cho DB.

11. Khi AI agent làm việc với module này

  • Mọi logic tính toán, xác thực thời gian, kiểm tra role phải đưa vào Service.
  • Repository đảm trách mọi truy vấn đến DB. Không import/sử dụng trực tiếp Prisma Client ở Controller hay Service.
  • Tuyệt đối không xóa logic kiểm tra status !== RequestStatus.PENDING.
  • Logic kiểm tra new Date() > expiresAt phải luôn đi trước việc update database.
  • Luôn kiểm soát đầu ra API thông qua thư viện class-transformer (plainToInstance) và cấu trúc DTO.
  • Khi lỗi truy vấn tin nhắn, thử hoán đổi senderId và receiverId vì Prisma OR có thể rỗng nếu UUID bị lệch. Theo vết expiresAt để check timezone bugs.
