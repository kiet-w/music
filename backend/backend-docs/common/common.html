Common Module

Thư mục Common không phải là một module tính năng thông thường mà là nơi chứa các thành phần chia sẻ (shared components) được sử dụng xuyên suốt toàn bộ ứng dụng NestJS. Bao gồm Filters, Interceptors, Interfaces, và Repositories cơ sở.

1. Tổng quan Kiến trúc (Component Overview)

Các thành phần trong thư mục common/ được thiết kế để tách biệt các vấn đề chung (cross-cutting concerns) ra khỏi logic nghiệp vụ (business logic).

2. Các Dependencies (Dependencies Injection)

Dependency Vai trò
HttpAdapterHost Được inject vào AllExceptionsFilter để có thể truy xuất HTTP adapter hiện tại (ví dụ Express) nhằm phản hồi request.
PinoLogger (nestjs-pino) Ghi log có cấu trúc về request, response và các lỗi (error/warn) trong AllExceptionsFilter và LoggingInterceptor.
PrismaService Được inject vào BaseRepository để cung cấp Prisma Client phục vụ việc truy vấn database.

3. Phân tích chi tiết Controller, Service, Guard, v.v.

Filters

  • AllExceptionsFilter (all-exceptions.filter.ts):
    • Decorator: @Catch() (bắt mọi loại exception).
    • Kế thừa: ExceptionFilter.
    • Logic: Bắt lỗi, kiểm tra nếu là HttpException hoặc Prisma Error. Thực hiện map các mã lỗi Prisma sang HTTP Status Code (P2002 -> 409, P2025 -> 404). Xây dựng body response theo format chung (statusCode, message, code, timestamp, path). Ghi log mức error hoặc warn.
  • HttpExceptionFilter (http-exception.filter.ts):
    • Decorator: @Catch(HttpException).
    • Kế thừa: ExceptionFilter.
    • Logic: Định dạng trực tiếp các HttpException thành JSON payload chuẩn.

Interceptors

  • LoggingInterceptor (logging.interceptor.ts):
    • Decorator: @Injectable().
    • Logic: Lấy thông tin request (method, url, query, v.v.). Dùng RxJS tap để đo đạc thời gian xử lý (duration). Ghi log mức info khi thành công, hoặc error khi thất bại.

Interfaces

  • IDownloaderProvider: Định nghĩa các hàm download(url, outputPath) và cleanup(filePath).
  • IStorageProvider: Định nghĩa các thao tác lưu trữ file như upload, uploadBuffer, getPublicUrl, và delete.

Repositories

  • BaseRepository (base.repository.ts):
    • Logic: Abstract class generic bao bọc các lời gọi tới Prisma.
    • Helper handlePrismaError(error): Dịch các mã lỗi Prisma thành các HttpException tương ứng để xử lý thống nhất.

5. Đánh giá — Đã tốt chưa?

✅ Đã làm tốt

Điểm tốt Lý do
Bắt lỗi Prisma tập trung Xử lý lỗi PrismaClientKnownRequestError giúp service không phải try-catch lặp lại liên tục.
Kế thừa BaseRepository Giảm code lặp ở các class con khi đóng gói các hàm Prisma cơ bản.
Logging chi tiết LoggingInterceptor ghi log kèm duration, query, params, hữu ích khi debug request cụ thể.

❌ Chưa tốt / Cần cải thiện

  • Trùng lặp logic bắt lỗi Prisma: Cả AllExceptionsFilter và BaseRepository đều cố gắng map lỗi Prisma. Nếu BaseRepository đã biến đổi nó thành HttpException, Filter sẽ không bắt được lỗi Prisma gốc nữa. Cần đưa về 1 nơi duy nhất.
  • Hai Filter xử lý Http Exceptions: Tồn tại cả AllExceptionsFilter và HttpExceptionFilter. Nên xóa bỏ HttpExceptionFilter dư thừa.

7. Cách Debug khi gặp lỗi

Lỗi 500 Internal Server Error ẩn:

  1. Xem log backend sinh bởi PinoLogger có message "Unhandled Exception" do AllExceptionsFilter sinh ra.
  2. Kiểm tra xem lỗi đó có thuộc về Prisma hay từ code logic.

Command debug: Chạy rtk log backend để theo dõi log JSON. Tìm từ khóa "statusCode": 500.

8. Các Pattern quan trọng

Pattern 1: Base Repository (Abstract Class Wrapper)

Abstract đi phần thao tác cơ bản với database. Code các Repo con chỉ việc kế thừa.

export abstract class BaseRepository<T, Delegate> {
  constructor(protected prisma: PrismaService, protected delegate: Delegate) {}
  
  async findUnique(args: any): Promise<T | null> {
    try {
      return await (this.delegate as any).findUnique(args);
    } catch (error) {
      return this.handlePrismaError(error);
    }
  }
}

Pattern 2: Global Exception Handling

Giúp Controller không bao giờ cần try/catch, luôn ném exception và có một lớp duy nhất đón để format lại chuỗi JSON trả về cho frontend.

@Catch()
export class AllExceptionsFilter implements ExceptionFilter { ... }

9. Biến môi trường & Nguyên tắc làm việc

Môi trường: Yêu cầu DATABASE_URL cho Prisma.

Khi AI agent làm việc với module này:

  • Phải chắc chắn thành phần được chia sẻ bởi ít nhất 2 module khác nhau.
  • Interface phải rõ ràng, chỉ chứa signature, không chứa implementation.
  • Lưu ý khi sửa Filters/Interceptors vì sẽ ảnh hưởng toàn bộ luồng request/response.
