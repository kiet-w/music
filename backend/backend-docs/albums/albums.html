Albums Module

Quản lý các album nhạc của người dùng trong hệ thống. Bao gồm các tính năng: tạo album mới, lấy danh sách album của người dùng (có phân trang), lấy chi tiết một album theo ID, và tìm hoặc tạo một album mặc định cho người dùng.

1. Kiến trúc tổng thể (Component Overview)

Kiến trúc được tổ chức theo Separation of Concerns, tách biệt các layer Controller (HTTP) -> Service (Business Logic) -> Repository (Database Query).

2. Các Dependencies

Dependency Vai trò
AlbumRepository Giao tiếp với DB để query và thao tác entity Album (kế thừa từ BaseRepository).
PinoLogger Ghi log chuẩn cấu trúc theo vết hoạt động (create, find).
PrismaService Inject vào AlbumRepository cung cấp Prisma Client query DB.

4. Phân tích chi tiết Controller & Service

AlbumController

@Controller('albums')
@UseGuards(JwtAuthGuard)
@UseInterceptors(ClassSerializerInterceptor)

Controller sử dụng các decorator của NestJS và Swagger để cấu hình route bảo mật bằng JWT và chuẩn hóa dữ liệu trả về thông qua DTO.

  • create(): Nhận body { title, artist, coverUrl } và gọi AlbumService.create(). Trả về AlbumResponseDto.
  • findAll(): Lấy danh sách phân trang bằng cách tính toán skip và take. Mặc định limit = 50.
  • findOne(): Lấy chi tiết bằng ID, ném NotFoundException nếu không tìm thấy.

AlbumService

Chứa toàn bộ logic nghiệp vụ, gọi Repository và mapping dữ liệu trả về client.

  • create(): Ghi log sự kiện và tạo album gán với userId.
  • findOrCreateDefault(): Xử lý race condition với cấu trúc Try-Catch. Cố gắng findDefault(), nếu không có tiến hành create() album "Default", nếu lỗi Unique Constraint xảy ra, catch lỗi và gọi lại findDefault().
  • findAll(): Tối ưu hóa truy vấn bằng Promise.all để chạy song song lệnh count và lệnh findMany.
  • mapAlbumResponse(): Ánh xạ dữ liệu _count.tracks sang _count.songs để phù hợp DTO.

5. API Design & DTO Pattern

DTO (Data Transfer Objects)

CreateAlbumDto: Validate bằng class-validator: @IsString, @IsNotEmpty, @IsUrl, @IsOptional.

AlbumResponseDto: Sử dụng @Expose() và @Type() kết hợp với ClassSerializerInterceptor ở Controller. Pattern này giúp ẩn đi các metadata từ ORM một cách tự động, bảo vệ cấu trúc CSDL bên dưới.

API Responses Shape

{
  "id": "uuid",
  "title": "Tên album",
  "artist": "Ca sĩ",
  "coverUrl": "URL ảnh",
  "tracks": [],
  "_count": {
    "songs": 10
  }
}

6. Đánh giá & Cải thiện (Best Practices)

✅ Đã làm tốt

  • Tenant Isolation: Truy vấn DB luôn đi kèm where: { userId }.
  • Race Condition Handling: Áp dụng pattern catch-and-retry hiệu quả.
  • Data Transfer Isolation: Sử dụng ClassSerializerInterceptor rất sạch sẽ.

❌ Cần cải thiện

  • Pagination tại Controller: Tính toán skip/take thủ công không an toàn. Nên sửa thành dùng ParseIntPipe hoặc PaginationDto.
  • Sử dụng type any: Type any tại @CurrentUser() user: any làm giảm sức mạnh của TypeScript. Nên sử dụng interface JWT Payload chuẩn.
