Songs Module

Quản lý các bài hát (Track) trong hệ thống: lấy danh sách, xóa, di chuyển bài hát và xử lý thêm bài hát từ YouTube qua Background Jobs (BullMQ).

1. Tổng quan Kiến trúc

Module Songs chịu trách nhiệm quản lý các bài hát (Track) trong hệ thống. Tính năng cốt lõi của module bao gồm: thêm bài hát mới từ nguồn YouTube, lấy danh sách tất cả bài hát của một người dùng (hỗ trợ phân trang), lấy chi tiết bài hát, xóa bài hát, và di chuyển bài hát giữa các Album.

Module này có sự kết nối chặt chẽ với AlbumsModule để xác thực quyền sở hữu album và JobsModule (sử dụng BullMQ) để đẩy tác vụ xử lý/tải âm thanh xuống chạy ngầm (Background Job) để tránh block main thread.

2. Các Dependencies

Dependency Vai trò
JobsModule / conversionQueue Cung cấp hàng đợi conversion thông qua BullMQ để xử lý việc convert video từ YouTube sang audio một cách bất đồng bộ. Tránh làm treo request HTTP.
AlbumsModule Nhúng AlbumService và AlbumRepository giúp tái sử dụng logic xác thực quyền truy cập album của người dùng mà không cần viết lại logic ở module Song.
SongRepository Kế thừa BaseRepository, làm tầng giao tiếp với database (Prisma) cho entity Track.
PinoLogger (nestjs-pino) Dùng để ghi log cấu trúc chuẩn (thông tin, cảnh báo vi phạm quyền truy cập, debug) trong quá trình xử lý logic.

3. System Data Flow & API Entry Points

1. POST /songs/youtube (Create from YouTube)

@Post('youtube')
createFromYoutube(@User() user, @Body() createSongDto: CreateSongYoutubeDto)

Nhận URL và thông tin bài hát từ body, gọi SongService.createFromYoutube() để lưu record tạm thời có sourceType: 'youtube', sau đó đẩy job convert vào background worker thông qua conversionQueue để download video và chuyển đổi audio async. Trả về DTO thông tin bài hát (SongResponseDto) sau lọc.

2. GET /songs (Find All)

@Get()
findAll(@User() user, @Query('page') page, @Query('limit') limit)

Lấy danh sách tất cả bài hát của một người dùng dựa theo album.userId = user.id. Có hỗ trợ phân trang bằng việc parse thủ công page và limit để tính skip và take. Gọi đồng thời (Promise.all) count() và findMany() để lấy cả tổng số và dữ liệu list. Trả về cấu trúc có data, total, page, limit, totalPages.

3. GET /songs/:id (Find One)

@Get(':id')
findOne(@User() user, @Param('id') id: string)

Lấy thông tin chi tiết của một bài hát bằng id. SongService sẽ gọi hàm helper nội bộ findAndValidateSong() nhằm tìm track trong DB, đồng thời kiểm tra track này có nằm trong album mà user đang sở hữu không.

4. DELETE /songs/:id (Remove)

@Delete(':id')
@HttpCode(204)
remove(@User() user, @Param('id') id: string)

Xóa bài hát theo id. Sau khi findAndValidateSong() thành công xác nhận quyền sở hữu, sẽ gọi SongRepository.delete(). Sử dụng status code chuẩn 204 No Content.

5. PATCH /songs/:id/move (Move to Album)

@Patch(':id/move')
moveToAlbum(@User() user, @Param('id') id: string, @Body('albumId') albumId: string)

Chuyển bài hát sang một album khác. Trước hết, findAndValidateSong() xác nhận track tồn tại và thuộc về user. Sau đó getValidatedAlbumId() gọi qua AlbumService để đảm bảo album đích (từ body params) cũng đang tồn tại và thuộc về user. Nếu mọi thứ hợp lệ, cập nhật albumId mới vào DB.

4. Đánh giá & Cải thiện

✅ Đã làm tốt

  • Background Job / Non-blocking: Sử dụng hàng đợi BullMQ để tránh gây nghẽn luồng xử lý HTTP khi thao tác tải và convert audio Youtube.
  • Data DTO Formatting (Serialization): Sử dụng plainToInstance với cấu hình excludeExtraneousValues: true trong helper mapToResponse đảm bảo Response trả về chuẩn, tự động che giấu các trường nhạy cảm trong DB (ví dụ password liên quan, cờ flag, ngày cập nhật, ...).
  • Quản lý quyền bài hát: Cách kiểm tra quyền truy cập thông qua relationship với Album (album: { userId }) được dùng nhất quán ở mọi function liên quan.
  • RESTful API & Status Codes: Đặt tên route resource sạch đẹp, dùng đúng Verb (POST, GET, PATCH, DELETE) và status code (vd dùng @HttpCode(204) cho DELETE).

5. Cách Debug & Biến môi trường

1. Debug Lỗi 404 NotFoundException (Track/Album)

Thông thường khi gặp lỗi này, log ghi là "Song not found or access denied" hoặc "Album not found or access denied". Cần kiểm tra theo thứ tự:

  1. Đảm bảo chuỗi UUID id của bài hát đúng định dạng.
  2. Kiểm tra albumId đích xem album này có thuộc quyền sở hữu của user (đại diện qua JWT token) không. Mọi bài hát hợp lệ phải nằm trong Album do user tạo.

2. Debug Lỗi: Bài hát tạo từ Youtube mãi không xử lý xong (không nghe được)

  1. Logic download xử lý qua BullMQ. Hãy chắc chắn Redis server đang chạy và kết nối bình thường ở JobsModule.
  2. Đọc log xuất ra từ Worker để xem job convert có bị timeout không, hoặc script parser/downloader từ Youtube bị block do network/captcha không.

3. Biến môi trường cần thiết

Do sự phụ thuộc vào JobsModule và hàng đợi, module Songs gián tiếp yêu cầu các biến môi trường của Redis:

# Required configuration cho BullMQ kết nối tới Redis
REDIS_HOST=127.0.0.1      # Host của redis
REDIS_PORT=6379           # Port của redis

4. Hướng dẫn dành cho AI / Maintainer

  • Mọi truy vấn tới Track luôn phải đi kèm cơ chế kiểm chứng quyền sở hữu qua Album (điều kiện truy vấn luôn có album: { userId }). Tuyệt đối không query độc lập chỉ bằng id track.
  • Khi nâng cấp / sửa tính năng Upload (ví dụ up file mp3 trực tiếp): Bắt buộc phải duy trì việc tách biệt task nặng bằng mô hình Message Queue (BullMQ). Tuyệt đối không nhúng logic xử lý/lưu file I/O block thẳng vào thread chính của Controller hoặc Service.
  • Mọi endpoint mới trả dữ liệu về entity Track phải đi qua helper function mapToResponse() hoặc mapToResponseArray() để serialize DTO chính xác.
