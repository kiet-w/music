Core (App)

Thành phần Core (bao gồm AppController và AppService) đóng vai trò là điểm vào (entry point) mặc định của ứng dụng NestJS. Nó cung cấp một endpoint gốc (/) cơ bản nhất để kiểm tra xem server có đang hoạt động và phản hồi đúng cách hay không.

1. Kiến trúc tổng thể (Architecture)

Separation of Concerns: AppController chỉ quan tâm tới việc định tuyến HTTP request ở route root, còn AppService cung cấp dữ liệu trả về thực tế. Việc tách biệt này giúp codebase tuân thủ nghiêm ngặt và nhất quán với kiến trúc chung của NestJS ngay từ đầu.

2. Các Dependencies

Dependency Vai trò
AppService Được inject vào AppController thông qua Dependency Injection để cung cấp logic sinh ra chuỗi phản hồi mặc định.

3. Phân tích chi tiết Controller & Service

AppController (app.controller.ts)

Định nghĩa class này là một controller để nhận và xử lý các HTTP requests từ phía client. Mặc định ánh xạ tới route gốc /.

  • @Controller(): Đánh dấu class là controller.
  • @Get(): Xử lý request GET tại route /.
@Get()
getHello(): string

Vai trò: Xử lý HTTP GET. Gọi phương thức getHello() của AppService và trả về kết quả.

AppService (app.service.ts)

Đánh dấu class này là một provider có thể được khởi tạo và quản lý bởi hệ thống Dependency Injection của NestJS.

  • @Injectable(): Cho phép class có thể được inject vào các component khác.
getHello(): string

Vai trò: Sinh ra một chuỗi văn bản tĩnh 'Hello World!'.

5. Đánh giá — Đã tốt chưa?

✅ Đã làm tốt

Điểm tốt Lý do
Tuân thủ kiến trúc chuẩn Đã tách bạch Controller và Service rõ ràng dù logic cực kỳ đơn giản. Giúp làm framework mẫu cho các thành phần phức tạp hơn.
Testable AppService được inject qua constructor nên có thể dễ dàng mock trong app.controller.spec.ts.

❌ Chưa tốt / Cần cải thiện

Thiếu tính ứng dụng thực tế (Chưa có Health Check ý nghĩa)

Hiện tại endpoint này chỉ trả về chuỗi văn bản cứng, không cung cấp trạng thái hệ thống. Nên chuyển đổi endpoint này thành một Health Check API thực thụ.

// HIỆN TẠI — vấn đề:
getHello(): string {
  return 'Hello World!';
}

// NÊN SỬA — lý do:
getHello(): Record<string, any> {
  return { 
    status: 'UP', 
    timestamp: new Date().toISOString() 
  };
}

6. API Design Review

  • Endpoint Naming: GET / ⚠️ Dùng cho root path. Trả về plain text không hữu ích lắm cho REST API.
  • Response Shape: Trả về plain text string "Hello World!"
  • HTTP Status Codes: 200 OK ✅

7. Cách Debug khi gặp lỗi

Lỗi 404 Not Found tại Root Path

Checklist:

  1. Đảm bảo AppController đã được khai báo trong mảng controllers của file cấu hình module (app.module.ts).
  2. Kiểm tra xem trong file main.ts có thiết lập app.setGlobalPrefix('api') hay không. Nếu có, route sẽ trở thành /api thay vì /.

Command debug: Xem log terminal ở thời điểm NestJS khởi động: Tìm dòng có chữ [RoutesResolver] AppController {/}:.

8. Các Pattern quan trọng

Dependency Injection

constructor(private readonly appService: AppService) {}

Giúp AppController không phải tự khởi tạo AppService bằng từ khóa new. Đảm bảo nguyên lý Inversion of Control (IoC), giúp code lỏng lẻo (loose coupling) và dễ viết unit test. Nếu không dùng pattern này, Controller sẽ gắn chặt cứng với implementation của Service.

9. Khi AI agent làm việc với module này

  • Trước khi thêm feature mới: Không nên nhồi nhét logic nghiệp vụ phức tạp vào AppController hay AppService. Các domain thực tế cần được tạo bằng Module riêng biệt.
  • Khi sửa phần nhạy cảm của module: Kiểm tra trước xem có các công cụ giám sát (monitoring tools) nào đang phụ thuộc vào việc gọi root / để ping trạng thái server (uptime) không.
  • Khi thêm endpoint mới: Khuyến nghị tạo controller mới. Tránh lạm dụng AppController.
