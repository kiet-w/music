Auth Module

Xử lý toàn bộ các luồng xác thực và cấp quyền truy cập vào hệ thống. Bao gồm đăng ký, đăng nhập email/password, đăng nhập Google OAuth, và liên kết Google Drive.

1. Kiến trúc tổng thể (Component Overview)

Module Auth chịu trách nhiệm xử lý toàn bộ các luồng xác thực (authentication) và cấp quyền truy cập vào hệ thống.

Tại sao tách các layer?

  • Separation of Concerns: Controller chỉ xử lý HTTP request/response. Service xử lý nghiệp vụ, Repository xử lý query DB.
  • Giúp code dễ test hơn (có thể dễ dàng mock Repository để test Service).
  • Tăng khả năng tái sử dụng (Guard, Decorator, Repository có thể dùng ở module khác).

2. Các Dependencies

Dependency Vai trò
UserRepository Giao tiếp với Database để query và thao tác với entity User qua Prisma.
JwtModule / JwtService Cung cấp JwtService dùng để tạo và xác thực JSON Web Token (JWT).
ConfigService Truy xuất các biến môi trường cấu hình (JWT_SECRET, JWT_EXPIRES_IN, GOOGLE_CLIENT_ID).
PinoLogger Dùng để ghi log các sự kiện trong quá trình xác thực (thành công/lỗi).
OAuth2Client SDK của Google (google-auth-library) để xác thực idToken lấy từ client.
PrismaModule Cung cấp Prisma instance cho quá trình tương tác DB.

3. System Data Flow

Chi tiết Luồng Dữ Liệu

  • 1. POST /auth/register: Client → Controller (register()) → Service (register()) → Repository (findByEmail()) → DB (Kiểm tra) → Service (Băm password qua bcrypt) → Repository (create()) → DB (Lưu) → Service (buildAuthResponse()) → Client.
  • 2. POST /auth/login: Client → Controller (login()) → Service (login()) → Repository (findByEmail()) → DB (Lấy hash) → Service (bcrypt.compare()) → Service (buildAuthResponse()) → Client.
  • 3. POST /auth/google: Client → Controller (googleLogin()) → Service (verifyGoogleToken()) → API Google Auth → Service (findOrCreateGoogleUser()) → Repository → DB → Service (buildAuthResponse()) → Client.
  • 4. GET /auth/me: Client → JwtAuthGuard → JwtService.verifyAsync() → Guard gán payload vào request.user → Controller (me()) → Service (me()) → Repository → DB → Client.
  • 5. GET /auth/google/status: Client → JwtAuthGuard → Controller → Service (getGoogleStatus()) → Repository → DB → Client.
  • 6. GET /auth/users: Client → JwtAuthGuard → Controller (xử lý query params) → Service (findAll()) → Repository (count() & findMany()) qua Promise.all → DB → Client.

4. Phân tích Chi tiết Component

AuthController (auth.controller.ts)

Các Decorators được sử dụng: @ApiTags, @Controller, @Post, @Get, @HttpCode, @UseGuards(JwtAuthGuard), @ApiBearerAuth(), @Body(), @Query(), @CurrentUser().

Public Endpoints

  • register(registerDto: RegisterDto): Trả về 201 Created hoặc 409 Conflict.
  • login(loginDto: LoginDto): Trả về 200 OK hoặc 401 Unauthorized.
  • googleLogin(googleLoginDto: GoogleLoginDto): Trả về 200 OK.
  • me(user): Yêu cầu JWT. Lấy user id và email từ token nhờ @CurrentUser().
  • googleStatus(user): Yêu cầu JWT. Trả về trạng thái liên kết Google của user.
  • findAll(page, limit): Yêu cầu JWT. Lấy tất cả user với phân trang.

AuthService (auth.service.ts)

Public Methods

  • register(dto): Chuẩn hóa email. Kiểm tra trùng (ném ConflictException nếu có). Băm password với bcrypt.hash, tạo user mới. Ghi log. Gọi buildAuthResponse().
  • login(dto): Tìm user. So khớp mật khẩu với bcrypt.compare. Gọi buildAuthResponse(). Ném UnauthorizedException nếu sai.
  • googleLogin(idToken): Gọi verifyGoogleToken, sau đó findOrCreateGoogleUser. Sinh token.
  • me(userId): Truy vấn user theo id từ repository. Trả về thông tin cơ bản.
  • getGoogleStatus(userId): Dựa vào googleRefreshToken để biết user đã liên kết Google Drive chưa.
  • findAll(skip, take): Gọi count() và findMany() qua Promise.all.

Private Helpers

  • buildAuthResponse(user): Tạo JWT Access Token (payload: sub = user.id, email = user.email), trả về cấu trúc AuthResponseDto.
  • verifyGoogleToken(idToken): Xác thực với Google. Nếu không có payload, ném lỗi UnauthorizedException.
  • findOrCreateGoogleUser(googleId, email, name): Tìm theo googleId. Nếu không có, tìm theo email để liên kết (update googleId). Nếu chưa tồn tại, tạo mới.

UserRepository, Guard, và Decorator

UserRepository (user.repository.ts)

Kế thừa BaseRepository<User, Prisma.UserDelegate>. Inject PrismaService. Cung cấp các hàm: findByEmail(email), findByGoogleId(googleId).

JwtAuthGuard (jwt-auth.guard.ts)

Kế thừa CanActivate. Trích xuất token. Nếu không có token → ghi log warn → 401. Dùng jwtService.verifyAsync. Thành công → gán vào request['user'].

CurrentUser Decorator (current-user.decorator.ts)

Lấy giá trị request.user được JwtAuthGuard gán, đưa vào Controller dưới dạng tham số.

5. API Design Review & Trạng thái

Endpoint Mô tả Đánh giá
POST /auth/register Đăng ký tài khoản (201 Created) ✅ Rõ ràng, dễ hiểu.
POST /auth/login Đăng nhập truyền thống (200 OK) ✅ Rõ ràng.
POST /auth/google Đăng nhập qua Google (200 OK) ✅ Chuẩn cho OAuth provider.
GET /auth/me Lấy profile (200 OK) ✅ Naming chuẩn RESTful.
GET /auth/google/status Kiểm tra liên kết Google ⚠️ Tạm ổn (tốt hơn nên ở /users/me/...).
GET /auth/users Lấy danh sách Users ❌ Không nên đặt ở auth module. Cần dời sang UsersController.

Response Shape chung: Trả về { accessToken: string, user: { id, email, name } }.

6. Đánh giá & Patterns

✅ Điểm tốt

  • Clean Architecture: Controller thuần HTTP. Repository xử lý DB. Service xử lý logic.
  • Error Logging: Sử dụng PinoLogger rất hữu ích cho security audit.
  • Account Linking: OAuth xử lý hoàn hảo việc liên kết với account email/password đã tồn tại trước đó thay vì báo lỗi.

❌ Cần cải thiện

  • Pagination thủ công: Hiện tại đang tự parse page, limit ở Controller. Nên tạo PaginationDto kết hợp Pipe validate.
  • Thiếu Role Guard: Endpoint GET /auth/users chưa kiểm tra quyền ADMIN, có rủi ro lộ data.

Pattern Áp dụng

  • Repository Pattern: Giảm sự ràng buộc giữa Service và ORM. Dễ test hơn.
  • Custom Parameter Decorator: Giấu đi chi tiết của Express request.user bằng @CurrentUser().

7. Hướng dẫn Debug

Lỗi 401 Unauthorized

  • Đã truyền token vào request header Authorization: Bearer <token> chưa?
  • Token đã hết hạn chưa? (Decode ra xem claim exp).
  • Giá trị JWT_SECRET trong .env đã đúng chưa?
  • Command: Xem log backend có báo 'Auth failed: Invalid token' không.

Lỗi 401 "Google authentication failed"

  • Token idToken gửi lên từ Client có đúng không?
  • Client ID trên Frontend có match với GOOGLE_CLIENT_ID trên Backend không?
  • Command: Xem log báo "Google login failed".
