Auth

Xử lý toàn bộ các luồng xác thực (authentication) và cấp quyền truy cập vào hệ thống. Bao gồm đăng ký, đăng nhập truyền thống, đăng nhập Google OAuth, liên kết Google Drive, và quản lý JWT Token.

1. Kiến trúc Tổng thể (Architecture Overview)

Tại sao tách các layer?

  • Separation of Concerns: Controller chỉ xử lý HTTP request/response. Service xử lý nghiệp vụ, Repository xử lý query DB.
  • Giúp code dễ test hơn (có thể dễ dàng mock Repository để test Service).
  • Tăng khả năng tái sử dụng (Guard, Decorator, Repository có thể dùng ở module khác).

2. System Data Flow

Flow: Register & Login Truyền thống

Flow: Google OAuth & Access

Chi tiết các luồng:

  • POST /auth/register: Client -> Controller (register()) -> Service (register()) -> Repository (findByEmail()) -> DB -> Service (bcrypt) -> Repository (create()) -> DB -> Service (buildAuthResponse() -> JwtService.sign()) -> Controller -> Client.
  • POST /auth/login: Client -> Controller (login()) -> Service (login()) -> Repository (findByEmail()) -> DB -> Service (bcrypt.compare()) -> Service (buildAuthResponse()) -> Controller -> Client.
  • POST /auth/google: Client -> Controller (googleLogin()) -> Service (googleLogin()) -> Service (verifyGoogleToken()) -> API Google Auth -> Service (findOrCreateGoogleUser()) -> DB -> Service (buildAuthResponse()) -> Controller -> Client.
  • GET /auth/me: Client -> JwtAuthGuard -> JwtService.verifyAsync() -> Controller (@CurrentUser()) -> Service (me()) -> Repository -> DB -> Client.
  • GET /auth/google/status: Client -> JwtAuthGuard -> JwtService.verifyAsync() -> Controller -> Service (getGoogleStatus()) -> Repository -> DB -> Client.
  • GET /auth/users: Client -> JwtAuthGuard -> JwtService.verifyAsync() -> Controller (findAll() xử lý pagination) -> Service (findAll()) -> Repository (count() & findMany()) -> DB -> Client.

4. Phân tích Chi tiết Component

AuthController (auth.controller.ts)

Các Decorators được sử dụng: @ApiTags, @Controller, @Post, @Get, @HttpCode, @UseGuards(JwtAuthGuard), @ApiBearerAuth(), @Body(), @Query(), @CurrentUser().


Public Endpoints
  • register(registerDto: RegisterDto): Trả về 201 Created hoặc 409 Conflict.
  • login(loginDto: LoginDto): Trả về 200 OK hoặc 401 Unauthorized.
  • googleLogin(googleLoginDto: GoogleLoginDto): Trả về 200 OK.
  • me(user): Yêu cầu JWT. Lấy user id và email từ token nhờ @CurrentUser().
  • googleStatus(user): Yêu cầu JWT. Trả về trạng thái liên kết Google của user.
  • findAll(page, limit): Yêu cầu JWT. Lấy tất cả user với phân trang.

AuthService (auth.service.ts)


Public Methods
  • register(dto): Chuẩn hóa email. Kiểm tra trùng (ném ConflictException nếu có). Băm password với bcrypt.hash, tạo user mới. Ghi log. Gọi buildAuthResponse().
  • login(dto): Tìm user. So khớp mật khẩu với bcrypt.compare. Gọi buildAuthResponse(). Ném UnauthorizedException nếu sai.
  • googleLogin(idToken): Gọi verifyGoogleToken, sau đó findOrCreateGoogleUser. Sinh token.
  • me(userId): Truy vấn user theo id từ repository. Trả về thông tin cơ bản.
  • getGoogleStatus(userId): Dựa vào googleRefreshToken để biết user đã liên kết Google Drive chưa.
  • findAll(skip, take): Gọi count() và findMany() qua Promise.all.
Private Helpers
  • buildAuthResponse(user): Tạo JWT Access Token (payload: sub = user.id, email = user.email), trả về cấu trúc AuthResponseDto.
  • verifyGoogleToken(idToken): Xác thực với Google. Nếu không có payload, ném lỗi UnauthorizedException.
  • findOrCreateGoogleUser(googleId, email, name): Tìm theo googleId. Nếu không có, tìm theo email để liên kết (update googleId). Nếu chưa tồn tại, tạo mới.

UserRepository, Guard, và Decorator


UserRepository (user.repository.ts)

Kế thừa BaseRepository<User, Prisma.UserDelegate>. Inject PrismaService. Cung cấp các hàm: findByEmail(email), findByGoogleId(googleId).

JwtAuthGuard (jwt-auth.guard.ts)

Kế thừa CanActivate. Trích xuất token. Nếu không có token → ghi log warn → 401. Dùng jwtService.verifyAsync. Thành công → gán vào request['user'].

CurrentUser Decorator (current-user.decorator.ts)

Lấy giá trị request.user được JwtAuthGuard gán, đưa vào Controller dưới dạng tham số.

5. API Design Review & Error Handling

Endpoint Naming

POST /auth/register       [✅] Rõ ràng, dễ hiểu.
POST /auth/login          [✅] Rõ ràng.
POST /auth/google         [✅] Đạt tiêu chuẩn cho OAuth provider login.
GET  /auth/me             [✅] Chuẩn RESTful cho thao tác lấy profile.
GET  /auth/google/status  [⚠️] Tốt hơn nên đặt tại /users/me/integrations/google.
GET  /auth/users          [❌] Không nên đặt list user trong auth module (Nên là /users).

Response Shape & Status Codes

Hướng dẫn Debug

Lỗi 401 Unauthorized khi truy cập API

  1. Đã truyền token vào request header Authorization: Bearer <token> chưa?
  2. Token đã hết hạn chưa? (Decode ra xem claim exp).
  3. Giá trị JWT_SECRET trong .env đã đúng chưa?
  4. Command debug: Xem log backend "Auth failed: Invalid token".

Lỗi 401 "Google authentication failed"

  1. Token idToken gửi lên từ Frontend có đúng do Google SDK trả về không?
  2. Client ID có match với GOOGLE_CLIENT_ID trên Backend không?
  3. Command debug: Xem log báo "Google login failed".

6. Đánh giá & Design Patterns

✅ Những điểm đã làm tốt

  • Clean Architecture: Controller thuần túy xử lý HTTP. Repository chỉ xử lý DB queries. Service gom nhóm business logic.
  • Error Logging: Sử dụng PinoLogger bắn ra cấu trúc chuẩn cho security audit.
  • Account Linking: Xử lý rất tốt tình huống người dùng từng tạo account email/password, sau đó đăng nhập bằng Google (cùng email). Nó liên kết thay vì tạo mới.

❌ Cần cải thiện (Technical Debt)

  • Tính toán Pagination thủ công: Controller tự parse page và limit dễ sinh lỗi. Nên tạo PaginationDto với Validation Pipe.
  • GET /auth/users thiếu phân quyền: Hiện tại endpoint này chỉ yêu cầu JWT. Nó có thể làm rò rỉ dữ liệu. Cần thêm @Roles('ADMIN') và RolesGuard.

Các Patterns quan trọng

Pattern 1: Repository Pattern với BaseRepository

Giúp giảm sự ràng buộc giữa Service và ORM. Dễ dàng mock khi viết Unit test và gom nhóm logic query tái sử dụng.

Pattern 2: Custom Parameter Decorator (@CurrentUser)

Giấu đi cấu trúc đối tượng request của Express, giúp controller tách biệt với framework nền tảng.

Khi AI agent làm việc với module này

  • Biến môi trường cần thiết: JWT_SECRET, JWT_EXPIRES_IN, GOOGLE_CLIENT_ID.
  • Luôn inject Repository thay vì Prisma trực tiếp.
  • KHÔNG thay đổi số vòng lặp bcrypt (đang là 12) vì có thể làm break account cũ.
  • KHÔNG thay đổi Payload Token (sub, email) nếu không update cả JwtAuthGuard.
