Root Module

Entry point chính của ứng dụng NestJS. Chịu trách nhiệm khởi tạo ứng dụng, thiết lập middleware, interceptors, filters toàn cục và nạp toàn bộ các sub-modules.

1. Kiến trúc tổng thể (Architecture Overview)

Tất cả các tuỳ chỉnh toàn cục (global pipeline) được thiết lập ở main.ts giúp người quản trị dễ dàng nhìn thấy toàn bộ middleware hoặc rules của ứng dụng. AppModule chỉ làm nhiệm vụ "lắp ráp" các building blocks (modules). Bằng cách khai báo global, mọi logic bắt lỗi và validate DTO được đồng nhất.

2. Các Dependencies Injection (Global Modules)

DependencyVai trò
ConfigModuleNạp biến môi trường từ file .env thành biến global dùng chung cho toàn bộ app (isGlobal: true) để mọi module khác đều có thể sử dụng.
LoggerModuleThay thế hệ thống log mặc định của Nest bằng thư viện Pino, giúp in log dưới dạng JSON có cấu trúc khi ở production, hỗ trợ tracking dễ hơn. Tích hợp pino-pretty ở môi trường dev.
CacheModuleCung cấp In-Memory Caching mặc định cho toàn app với TTL 60s.

3. Entry Points & Bootstrap Flow

main.ts : bootstrap()
  1. Gọi config({ override: true }) từ dotenv để nạp cấu hình hệ thống (ưu tiên biến môi trường từ .env).
  2. Sử dụng NestFactory.create với option { bufferLogs: true }.
  3. Cấu hình custom logger (Pino) lấy từ DI container: app.useLogger(logger).
  4. Thiết lập CORS (app.enableCors) cho phép mọi credentials, origin.
  5. Gắn Global AllExceptionsFilter bắt mọi exception toàn cục.
  6. Gắn Global ValidationPipe với các option: whitelist: true, forbidNonWhitelisted: true, transform: true.
  7. Khởi tạo Swagger qua DocumentBuilder và SwaggerModule.setup.
  8. Khởi động HTTP Server trên process.env.PORT (mặc định 3000/3002).

4. Phân tích chi tiết: AppModule & Root Configs

AppModule (app.module.ts)

  • imports: Chứa các thư viện bên ngoài (ConfigModule, LoggerModule, CacheModule) và các sub-modules nghiệp vụ (Auth, Songs, Albums...).
  • controllers: Đăng ký AppController để làm một endpoint health check đơn giản.
  • providers: Khai báo AppService và cung cấp LoggingInterceptor sử dụng token APP_INTERCEPTOR. Mọi request/response sẽ tự động đi qua nó.

Root Configurations

  • package.json: Chứa project info, scripts (build, start, lint), và danh sách dependencies như @nestjs/core, @prisma/client, bullmq, nestjs-pino, supabase-js.
  • .env: Lưu trữ biến môi trường (PORT, DATABASE_URL, DIRECT_URL, NODE_ENV, thông tương OAuth, JWT_SECRET).
  • nest-cli.json: Cấu hình CLI cho NestJS (vd: deleteOutDir: true).
  • tsconfig.json: Cấu hình TypeScript compiler (tắt strictNullChecks, bật experimentalDecorators).

5. Các Pattern quan trọng

Pattern: Global Decorator/Interceptor qua APP_* Token

Thay vì dùng app.useGlobalInterceptors(new LoggingInterceptor()) ở main.ts, việc dùng APP_INTERCEPTOR trong app.module.ts giúp Interceptor nằm trong vòng quản lý của DI container. Từ đó có thể Inject các service khác (ví dụ: Database logging) một cách dễ dàng.

{
  provide: APP_INTERCEPTOR,
  useClass: LoggingInterceptor,
}

6. Đánh giá — Đã tốt chưa?

✅ Đã làm tốt

  • Sử dụng nestjs-pino: Hiệu năng tốt hơn, in log dưới chuẩn JSON phù hợp cho ELK stack / Datadog khi deploy cloud.
  • Validation Pipe chặt chẽ: Option whitelist: true và forbidNonWhitelisted: true gạt bỏ thuộc tính rác, ngăn chặn lỗ hổng Mass Assignment.
  • Tách biệt môi trường cho Logger: Config pino-pretty cho dev dễ nhìn log, dùng dạng thô trên production để tối ưu tài nguyên.

❌ Cần cải thiện

  • Khai báo CacheModule chưa tối ưu cho Scale: Hiện tại đang dùng in-memory (TTL 60s). Nếu horizonal scaling ra nhiều nodes, cache sẽ bị lệch (inconsistent). Nên dùng Redis.
  • Cấu hình .env chưa có Validation: Nên tích hợp Joi vào ConfigModule.forRoot({ validationSchema: ... }) để validate các biến môi trường khi start app, tránh lỗi ẩn ở Runtime do quên điền biến.

7. Cách Debug khi gặp lỗi

Lỗi Crash khi khởi động (Exit Code 1)

  • Checklist: Kiểm tra lại file .env đã đủ biến chưa; kiểm tra xem port (3002) có đang bị chiếm không.
  • Command: Chạy rtk env để kiểm tra cấu hình. Chạy lệnh start bằng tay để xem callstack.

Lỗi Validation Pipe (400 Bad Request với field lạ)

  • Checklist: Xác định DTO của endpoint đang thiếu khai báo @IsString(), @IsOptional()... nên bị whitelist bắt lại. Cập nhật class DTO đó bằng các class-validator decorators cho khớp.

8. Khi AI agent làm việc với module này

  • Bất cứ module độc lập nghiệp vụ nào được tạo ra, bắt buộc phải khai báo vào list imports của AppModule thì nó mới có hiệu lực.
  • Bất cứ module cấu hình chia sẻ nào muốn gọi mọi nơi không cần import lại, cần set isGlobal: true lúc đăng ký.
  • KHÔNG vô hiệu hóa whitelist: true và forbidNonWhitelisted: true của ValidationPipe vì đây là cơ chế phòng vệ bảo mật cơ bản nhất.
  • Khi debug, quan sát log console nhờ pino-pretty. Mọi exception sẽ được in ra với timestamp nhờ global filter.
